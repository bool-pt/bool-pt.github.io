# Internationalization (i18n)

Bool uses a custom, lightweight i18n system built around flat JSON translation files, a type-safe lookup function, and a props-down data flow. The system spans three layers: the `@bool/i18n` package (translation engine), the Astro app (consumer), and the json-editor app (visual editing tool).

---

## Architecture Overview

```
┌─────────────────────────────────────────────────────────────────────┐
│  @bool/i18n                                                         │
│  packages/i18n/src/locales/en.json  ──►  t(key, locale) → string   │
└──────────────────────────┬──────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────────────┐
│  Astro App — apps/web/bool/                                         │
│                                                                     │
│  src/labels.ts                                                      │
│    getHeaderLabels()  ─┐                                            │
│    getFooterLabels()   │                                            │
│    getContactFormLabels() ...                                       │
│                        │                                            │
│  src/pages/*.astro     │                                            │
│    t() direct calls  ──┤──►  Section props  ──►  Composition props  │
│    getXxxLabels()    ──┘                                            │
└─────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────┐
│  JSON Editor — apps/web/json-editor/                                │
│                                                                     │
│  Upload en.json  ──►  parseFlatJson()  ──►  Visual Editor           │
│                                              ↓                      │
│                                         serialize()  ──►  Download  │
└─────────────────────────────────────────────────────────────────────┘
```

**Key rule**: Components never call `t()` directly. All translated strings flow as props from pages downward through the component tree.

## The `@bool/i18n` Package

**Location**: `packages/i18n/`

### Public API

```typescript
// packages/i18n/index.ts
export { t, tOptional, enKeys } from './src/t.ts';
export { tCollection, tList } from './src/collection.ts';
export type { TranslationKey } from './src/t.ts';
export { defaultLocale, locales, isValidLocale, LOCALE_META, translations } from './src/config.ts';
export type { Locale } from './src/config.ts';
```

| Export           | Type       | Description                                                            |
| ---------------- | ---------- | ---------------------------------------------------------------------- |
| `t`              | `function` | Translation lookup: `t(key, locale?) → string`                         |
| `tOptional`      | `function` | Like `t()` but returns `undefined` when the key is missing             |
| `tCollection`    | `function` | Auto-discover numbered object arrays from JSON keys                    |
| `tList`          | `function` | Auto-discover numbered string arrays from JSON keys                    |
| `TranslationKey` | `type`     | Union of all valid keys from `en.json`                                 |
| `defaultLocale`  | `const`    | `'en'`                                                                 |
| `locales`        | `const`    | `string[]` — auto-discovered from locale JSON files                    |
| `isValidLocale`  | `function` | Type guard: narrows `string` to `Locale`                               |
| `Locale`         | `type`     | `string` (any discovered locale code)                                  |
| `enKeys`         | `const`    | `string[]` — all top-level keys from `en.json`                         |
| `translations`   | `const`    | `Record<string, Record<string, string>>` — all locale data             |
| `LOCALE_META`    | `const`    | `Record<string, { flag: string; name: string }>` — locale display info |

### The `t()` Function

```typescript
// packages/i18n/src/t.ts
import { translations, defaultLocale } from './config';
import type { Locale } from './config';
import type en from './locales/en.json';

export type TranslationKey = keyof typeof en;

export const enKeys: string[] = Object.keys(translations['en'] ?? {});

export function t(key: string, locale: Locale = defaultLocale): string {
  return translations[locale]?.[key] ?? translations['en']?.[key] ?? key;
}
```

**`TranslationKey`** is exported as a type union of all keys in `en.json` for IDE autocompletion. The `key` parameter accepts `string` at runtime for compatibility with dynamic key construction (e.g. `tCollection` building keys from prefixes).

**`enKeys`** is the array of all keys from the dynamically discovered English translations, used internally by `tCollection()` and `tList()` to discover numbered items.

**Fallback chain** (evaluated left to right, relevant when multiple locales exist):

1. Translation in the requested locale
2. Translation in English (`'en'`)
3. The key string itself (graceful degradation — never crashes)

### Collection Utilities: `tCollection()` and `tList()`

**Location**: `packages/i18n/src/collection.ts`

These utilities auto-discover numbered arrays from the flat JSON keys at build time. `en.json` is always the source of truth for which items exist — other locales fall back via `t()`.

#### `tCollection(prefix, fields, locale?)`

Scans for keys matching `prefix.N.field` and returns an array of objects:

```typescript
// en.json: teamTestimonials.1.quote, teamTestimonials.1.name, teamTestimonials.2.quote, ...
const testimonials = tCollection('teamTestimonials', ['quote', 'name', 'role']);
// → [{ quote: "Great work", name: "John", role: "CTO" }, { quote: "Excellent", ... }]
```

Supports dot-notation nested fields:

```typescript
const slides = tCollection('hero.slides', [
  'title',
  'subtitle',
  'cta.primary.label',
  'cta.primary.href',
]);
// → [{ title: "...", subtitle: "...", "cta.primary.label": "...", "cta.primary.href": "/services" }]
```

#### `tList(prefix, locale?)`

Scans for keys matching `prefix.N` (simple numbered values) and returns a `string[]`:

```typescript
// en.json: knowledgeCenter.filters.1 = "All", knowledgeCenter.filters.2 = "OutSystems", ...
const filters = tList('knowledgeCenter.filters');
// → ["All", "OutSystems", "Mendix", "Power Platform", ...]
```

#### Adding items to a collection

To add a 5th hero slide, add these keys to `en.json` (and any other locale files):

```json
"hero.slides.5.title": "New Slide Title",
"hero.slides.5.subtitle": "New slide description",
"hero.slides.5.cta.primary.label": "CTA Label",
"hero.slides.5.cta.primary.href": "/target-page",
"hero.slides.5.cta.secondary.label": "Secondary CTA",
"hero.slides.5.cta.secondary.href": "/contacts"
```

No code changes needed — `tCollection('hero.slides', ...)` automatically discovers the new index.

#### Key naming rules for collections

- Use **numeric indices** starting from `1`: `prefix.1.field`, `prefix.2.field`
- Indices must be **consecutive digits** (no gaps required, but recommended)
- Zero-padded indices (`01`, `02`) are supported and sorted numerically
- The **first field** in the `fields` array is used for index discovery — every item must have it
- `en.json` determines which items exist; missing keys in other locales fall back to English

### Locale Configuration

```typescript
// packages/i18n/src/config.ts
const localeModules = import.meta.glob<Record<string, string>>('./locales/*.json', {
  eager: true,
  import: 'default',
});

// Locales are auto-discovered from JSON files in ./locales/
// Each file must include _locale.flag and _locale.name metadata keys

export const defaultLocale = 'en';

export type Locale = string;
export const LOCALE_META: Record<string, { flag: string; name: string }> = discoveredMeta;

export function isValidLocale(value: string): value is Locale {
  return locales.includes(value);
}
```

Locales are **dynamically discovered** from JSON files in `packages/i18n/src/locales/`. Currently only English (`en.json`) exists. To add a new locale, drop a JSON file in the folder — no code changes needed (see [Adding a New Locale](#adding-a-new-locale)).

## Translation File Format

**Location**: `packages/i18n/src/locales/en.json`

The file is a **flat JSON object** where every key is a dot-notation string and every value is a string. No nesting.

```json
{
  "_meta.pages.home": "hero, newsletterBar, powerAi, serviceCards, ...",
  "_meta.labels.hero": "Hero",
  "nav.about": "About",
  "hero.title": "We get it done!",
  "contactForm.email.placeholder": "your@email.com"
}
```

### Key Naming Convention

Keys follow the pattern `section.element.property`:

| Pattern                    | Example                         | Purpose                             |
| -------------------------- | ------------------------------- | ----------------------------------- |
| `section.property`         | `hero.aria`                     | Simple section field                |
| `section.element.property` | `contactForm.email.placeholder` | Nested element within section       |
| `section.items.N.property` | `hero.slides.1.title`           | Collection item (for `tCollection`) |
| `section.items.N`          | `knowledgeCenter.filters.1`     | Simple list value (for `tList`)     |
| `pageMeta.page.property`   | `pageMeta.home.title`           | SEO metadata                        |

The **first segment** determines the section (used by the json-editor for grouping).

### Metadata Keys (`_meta.*`)

Metadata keys drive the json-editor's navigation and are preserved during round-trip editing. They are not used at runtime by the Astro app.

| Key pattern               | Example                                                                  | Purpose                                     |
| ------------------------- | ------------------------------------------------------------------------ | ------------------------------------------- |
| `_meta.pages.<page>`      | `"_meta.pages.home": "hero, newsletterBar, powerAi, serviceCards, ..."`  | Declares which sections appear on each page |
| `_meta.shared`            | `"_meta.shared": "contactForm, newsletterCta, nav, header, footer, ..."` | Lists sections shared across multiple pages |
| `_meta.labels.<section>`  | `"_meta.labels.hero": "Hero"`                                            | Human-readable section labels               |
| `_meta.pageLabels.<page>` | `"_meta.pageLabels.home": "Home"`                                        | Human-readable page labels                  |

### Content Categories

The translation file covers the entire site. Key prefixes map to site areas:

| Prefix                                | Content                                       |
| ------------------------------------- | --------------------------------------------- |
| `nav.*`                               | Main navigation links                         |
| `header.*`, `footer.*`                | Layout shell (logo, social, legal, copyright) |
| `hero.*`                              | Homepage hero section                         |
| `aboutHero.*`, `servicesHero.*`, etc. | Page-specific hero sections                   |
| `contactForm.*`                       | Contact form fields, states, messages         |
| `newsletter.*`                        | Newsletter subscription form                  |
| `testimonials.*`                      | Client testimonials                           |
| `serviceCards.*`                      | Service listings                              |
| `pageMeta.*`                          | SEO meta titles and descriptions              |
| `common.*`                            | Shared UI strings (Close, Learn more, etc.)   |
| `cookie.*`                            | Cookie consent banner                         |
| `theme.*`                             | Dark/light mode toggle labels                 |
| `carousel.*`                          | Carousel navigation and ARIA labels           |

### Value Formats

Values are plain strings, but may contain:

- **HTML**: `"powerAi.heading": "AI in Everything We Do.<br />It's not an extra, it's our <strong>core</strong>"`
- **Placeholders**: `"carousel.slide.aria": "Slide {index} of {total}"` (interpolated by components)
- **Comma-separated lists**: `"calendar.days": "Mon,Tue,Wed,Thu,Fri,Sat,Sun"` (split by consumer)

## Main App Integration

### Astro i18n Configuration

```typescript
// apps/web/bool/astro.config.ts
import { locales, defaultLocale } from '@bool/i18n';

i18n: {
  defaultLocale,
  locales: [...locales],  // auto-populated from locale JSON files
  routing: { prefixDefaultLocale: false },
}
```

Locales are imported dynamically from `@bool/i18n` — adding a new JSON file to `packages/i18n/src/locales/` automatically registers it. URLs for the default locale are not prefixed (`/about`, not `/en/about`).

### Page Consumption Pattern

Every page follows the same pattern:

1. Import `t` from `@bool/i18n` for page-specific strings
2. Import `getXxxLabels` helpers from `../labels` for shared layout/component strings
3. Pass everything as props to section components

```astro
---
// apps/web/bool/src/pages/index.astro
import { t, tCollection } from '@bool/i18n';
import { getHeaderLabels, getFooterLabels, getContactSectionProps } from '../labels';

// Auto-discovered from hero.slides.1.*, hero.slides.2.*, etc. in en.json
const heroSlides = tCollection(
  'hero.slides',
  [
    'title',
    'subtitle',
    'cta.primary.label',
    'cta.primary.href',
    'cta.secondary.label',
    'cta.secondary.href',
  ],
  locale
).map((s) => ({
  title: s.title,
  subtitle: s.subtitle,
  ctas: {
    primary: { label: s['cta.primary.label'], href: s['cta.primary.href'] },
    secondary: { label: s['cta.secondary.label'], href: s['cta.secondary.href'] },
  },
}));
---

<BaseLayout
  title={t('pageMeta.home.title')}
  description={t('pageMeta.home.description')}
  headerLabels={getHeaderLabels()}
  footerLabels={getFooterLabels()}
>
  <HeroSection ariaLabel={t('hero.aria')} slides={heroSlides} />
  <ServicesSection heading={t('serviceCards.heading')} services={serviceItems} />
  <ContactSection {...getContactSectionProps()} />
</BaseLayout>
```

### Data Flow Summary

```
en.json
  ├──► t('hero.aria')                          single string lookup
  ├──► tCollection('hero.slides', [...])       auto-discovers hero.slides.1.*, .2.*, etc.
  └──► tList('knowledgeCenter.filters')        auto-discovers filters.1, .2, etc.
         └──► props objects
                └──► <HeroSection slides={...} />  passed to section
                       └──► <HeroCarousel />       forwarded to compositions
```

**Rules**:

- `t()`, `tCollection()`, and `tList()` are only called in `labels.ts` and page frontmatter (`---` blocks)
- Sections, compositions, and primitives receive all strings via props
- Components are locale-agnostic and reusable
- Collections are data-driven: add keys to `en.json` → items appear automatically at build time

## JSON Editor

The json-editor (`apps/web/json-editor/`) is a standalone Vite + React SPA for visually editing flat JSON files like `en.json`. It has no dependency on `@bool/i18n` — it works with any flat `Record<string, string>` JSON file.

### Workflow

```
1. Upload    User drags en.json into the editor
                 ↓
2. Parse     parseFlatJson() → sections, pages, repeating groups
                 ↓
3. Edit      Visual editor with search, undo/redo, drag-reorder
                 ↓
4. Download  serialize() → flat JSON → browser download
                 ↓
5. Replace   User copies downloaded file back to packages/i18n/src/locales/en.json
```

### Core Library: `@bool/json-editor-core`

**Location**: `packages/json-editor/`

Pure TypeScript library with zero runtime dependencies. Handles parsing, serialization, detection, and operations.

#### Parsing (`parser.ts`)

`parseFlatJson(json)` converts a flat JSON object into a structured tree:

1. **Extracts metadata** from `_meta.*` keys → page definitions, shared sections, labels
2. **Groups keys by first segment** → sections (e.g., all `hero.*` keys form the "hero" section)
3. **Detects repeating groups** within each section (see below)
4. **Separates fields** into simple fields and repeating group items
5. **Generates labels** from `_meta.labels.*` or camelCase-to-Title-Case fallback

#### Repeating Group Detection (`detector.ts`)

The editor automatically detects two types of repeating structures:

**Numeric groups** — keys with numeric indices:

```json
"testimonials.1.quote": "Great work",
"testimonials.1.author": "John",
"testimonials.2.quote": "Excellent",
"testimonials.2.author": "Jane"
```

Requires 2+ distinct indices to qualify.

**Named groups** — 3+ siblings with identical field structures:

```json
"techStack.outsystems.expert": "...",
"techStack.outsystems.feature1": "...",
"techStack.mendix.expert": "...",
"techStack.mendix.feature1": "...",
"techStack.salesforce.expert": "...",
"techStack.salesforce.feature1": "..."
```

Requires 3+ named siblings with matching suffix sets.

#### Serialization (`serializer.ts`)

`serialize(sections, metaKeys)` reverses parsing back to flat JSON:

- Reconstructs `_meta.*` keys first
- Flattens simple fields, then repeating group items
- Preserves original key order for minimal diffs in version control

`serializeToString()` wraps the result with `JSON.stringify(obj, null, 2)` and a trailing newline.

#### Operations (`operations.ts`)

All operations are immutable (return new arrays, never mutate input):

| Function                                  | Description                                  |
| ----------------------------------------- | -------------------------------------------- |
| `updateField(sections, key, value)`       | Updates a single field value, marks it dirty |
| `addItem(sections, groupPrefix)`          | Adds a new item to a repeating group         |
| `removeItem(sections, prefix, index)`     | Removes an item, renumbers if numeric        |
| `reorderItem(sections, prefix, from, to)` | Drag-reorder, always renumbers after move    |

### Editor Features

#### Sidebar Navigation

- **Page groups** (collapsible): shows sections assigned to each page via `_meta.pages.*`
- **Shared group**: sections listed in `_meta.shared`
- **Other group**: unassigned sections
- Dirty indicator on modified sections

#### Section Editing

- Fields displayed as input or textarea (based on value length)
- Fields in shared sections are **read-only** when accessed from page context, with a banner: _"This section is shared across multiple pages. [Edit in Shared]"_
- Search across all fields with highlighted results

#### Repeating Groups

- **Add item**: creates new item with all template fields (empty values)
- **Remove item**: confirms, then removes and renumbers
- **Drag-reorder**: reorder items with drag handles, auto-renumbers indices
- **Collapse/expand**: each item shows preview of first non-empty field

#### Other Features

- **Undo/redo**: up to 50 levels of history
- **Session persistence**: auto-saves to `sessionStorage` every second (survives page refresh, lost on tab close)
- **Dark mode**: toggle in top bar
- **Keyboard shortcuts**: Ctrl+Z / Ctrl+Shift+Z for undo/redo, Ctrl+S for download

### Editor's Own UI Translations

The json-editor has its own translation system for its UI (separate from the content being edited):

- **Location**: `apps/web/json-editor/src/locales/`
- **Files**: `en.json` (64 keys), `index.ts` (lookup function `l()`)
- Covers upload errors, sidebar labels, editor chrome, repeating group actions, and confirmation dialogs
- Supports future locale expansion via `setLocale()`

## Adding a New Locale

To add a new locale (e.g., Portuguese `pt`):

### 1. Create the translation file

Copy `packages/i18n/src/locales/en.json` to `packages/i18n/src/locales/pt.json` and translate all values. Keep all keys identical — only values change.

Add locale metadata keys at the top of the new file:

```json
{
  "_locale.flag": "🇵🇹",
  "_locale.name": "Português",
  "nav.about": "Sobre",
  ...
}
```

### 2. No code changes needed in `@bool/i18n`

The locale is **automatically discovered** by `config.ts` via `import.meta.glob('./locales/*.json')`. No manual registration in `config.ts` or `t.ts` is required.

### 3. No Astro configuration changes needed

`apps/web/bool/astro.config.ts` imports `locales` dynamically from `@bool/i18n`, so new locales are picked up automatically:

```typescript
import { locales, defaultLocale } from '@bool/i18n';

i18n: {
  defaultLocale,
  locales: [...locales],  // ← auto-populated from locale JSON files
  routing: { prefixDefaultLocale: false },
}
```

### 4. Update pages to accept locale

Pages will need to pass the current locale to `t()`. The exact routing strategy (prefix-based `/pt/about` or subdomain-based) depends on Astro's i18n routing configuration. With `prefixDefaultLocale: false`, English pages stay at `/about` while Portuguese pages would be at `/pt/about`.

### 5. Use the json-editor for translation

Upload the new `pt.json` to the json-editor, translate values visually, download, and replace the file.

## Adding New Translation Keys

When adding new content to the site that needs translated strings:

### 1. Add keys to `en.json`

Add new entries to `packages/i18n/src/locales/en.json`. Follow the naming convention:

```json
"newSection.heading": "My New Heading",
"newSection.body": "Some body text",
"newSection.cta": "Learn More"
```

If the section appears on a page, update the `_meta.pages.*` key to include it. If it's shared across pages, add it to `_meta.shared`. Add a label with `_meta.labels.newSection`.

### 2. Use in pages

For single strings, call `t()`. For collections, use `tCollection()` or `tList()`:

```astro
---
import { t, tCollection, tList } from '@bool/i18n';

const heading = t('newSection.heading');
const items = tCollection('newSection.items', ['title', 'body']);
const filters = tList('newSection.filters');
---

<NewSection heading={heading} items={items} filters={filters} />
```

### 3. Accept strings as props in components

The section component receives all data via props — never calls `t()`:

```typescript
interface Props {
  heading: string;
  items: Array<{ title: string; body: string }>;
  filters: string[];
}
```

### 4. Update other locale files

Add the same keys to every locale file in `packages/i18n/src/locales/` with translated values.

### 5. Adding items to existing collections

To add a new item to an existing collection, just add numbered keys to `en.json`:

```json
"teamTestimonials.4.quote": "New testimonial text",
"teamTestimonials.4.name": "New Person",
"teamTestimonials.4.role": "New Role"
```

No code changes needed — `tCollection()` auto-discovers the new index at build time.
